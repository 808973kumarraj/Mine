Full response
Per the Hermes docs, there are three separate axes: where Hermes itself is installed, how you talk to it, and where its commands execute.

Where Hermes itself runs

- Local CLI install: Linux, macOS or WSL2 via `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash`; native Windows via the PowerShell installer. Then run `hermes`.
- Hermes Desktop: packaged app for Windows and macOS (Apple Silicon only). It can also connect to a Hermes backend on another machine via Settings → Gateways.
- Docker image: `nousresearch/hermes-agent`, with data mounted at `/opt/data`. Run it interactively or as a persistent gateway (`gateway run`), optionally with Docker Compose and the dashboard.
- VPS or server: install as a dedicated service user and run it as a long-lived user service.
- Android: Termux APT package (aarch64).
- Nix / NixOS: flake and NixOS module, best-effort only.
- Source checkout: for development.

How you talk to it

- Terminal CLI or the Desktop app.
- Messaging gateway: Telegram, Discord, Slack, WhatsApp, Signal, Matrix, Mattermost, Email, SMS, Microsoft Teams, Google Chat, Home Assistant and others (20+ platforms from one gateway). Set it up with `hermes gateway setup`.
- OpenAI-compatible API server: the gateway exposes one on port 8642, so external tools can call it.
- Web dashboard: port 9119 when `HERMES_DASHBOARD=1` is set in the Docker image.
- Voice mode: in the CLI, Telegram and Discord.
- Scheduled cron jobs: unattended runs with results delivered to any platform.
- Bot Mode: named bots with their own model, memory and skills, working in group chats.

Where its commands execute (`terminal.backend` in `config.yaml`)

- `local`: directly on your machine, no isolation.
- `docker`: one persistent sandbox container.
- `ssh`: a remote server.
- `modal`: a Modal cloud sandbox, with filesystem snapshots between sessions.
- `daytona`: a Daytona workspace that hibernates when idle.
- `vercel_sandbox`: a cloud microVM.
- Plugin backends: Singularity/Apptainer (HPC clusters) and Sprites (Fly.io).

These combine freely. A common setup is the gateway on a cheap VPS, chat through Telegram, and commands executing in Docker or Modal.

Full response
Hermes Agent's core is the same everywhere; what varies is the interface you talk to it through, where its commands execute, and where the process is hosted.

**Interfaces**
- **Classic CLI:** `hermes` for interactive chat, or `hermes chat -q "..."` for a one-shot query (scriptable, good for CI or pipelines).
- **Ink TUI:** `hermes --tui`, or set `display.interface: tui` (this is what you're in now).
- **Desktop app:** `hermes desktop` (alias `hermes gui`), a native Electron app for macOS, Linux and Windows.
- **Web dashboard:** `hermes dashboard`, an admin panel with an embedded chat.
- **IDE integration:** an ACP server for VS Code, Zed and JetBrains.
- **Messaging gateway:** one gateway serves Telegram, Discord, Slack, WhatsApp, Signal, Matrix, Teams, Email, SMS and more (20+ platforms), with full tool access.
- **Bot Mode:** named bots with their own model, memory, skills and routines, working in group chats via `@mentions`.
- **OpenAI-compatible proxy:** `hermes proxy` exposes a local OpenAI API backed by your signed-in OAuth provider, so tools like Codex CLI, Aider or Cline can point at it.

**Where commands execute (terminal backends)**
- **Local:** directly on the host machine.
- **Docker:** inside a container, for isolation.
- **SSH:** on a remote machine.
- **Daytona or Modal:** serverless environments that hibernate when idle.
- **Vercel Sandbox:** another built-in sandbox option.
- **Plugin backends:** for example Singularity.

**Where the agent is hosted**
- **Your own machine:** Linux, macOS, WSL2 or native Windows.
- **Nix / NixOS:** supported as an install target.
- **Android:** via Termux on aarch64 devices.
- **A VPS or cloud VM:** run the gateway there and talk to it from Telegram or the desktop app's remote-gateway login.
- **A GPU cluster:** the docs list this as a supported home, typically alongside local models.

**Unattended and multi-instance modes**
- **Cron jobs:** scheduled tasks with delivery to any connected platform.
- **Webhooks:** event-driven runs triggered by external systems.
- **Profiles:** multiple independent instances with isolated config, sessions, skills and memory.
- **Spawned instances:** extra `hermes` processes in tmux or the background (`hermes -w` uses a git worktree to avoid conflicts), or `delegate_task` subagents for short parallel work.
- **Batch and research:** batch processing, trajectory export and RL training with Atropos.

This comes from the official docs landing page and the bundled `hermes-agent` skill; I did not run any of these modes here. For setup detail on any one of them, the index at https://hermes-agent.nousresearch.com/docs/llms.txt links to the relevant page.
