01 · Architecture

One driver, many executors

A Spark application is a driver process that plans the work and a set of executor processes that do it. A cluster manager hands out the machines. Run a job below, and click any box to see what it does.

Press Run a job to follow an action such as df.count() through the cluster.

What happens in a job

  1. Driver asks the cluster manager for resources
  2. Cluster manager launches executors
  3. Driver turns your code into a DAG of stages and tasks
  4. Tasks are shipped to executors
  5. Executors run tasks, one per partition per core
  6. Results and status flow back to the driver

02 · Data abstractions

RDD vs DataFrame

Both are distributed, immutable, partitioned collections evaluated lazily. The difference is how much Spark knows about your data. An RDD holds opaque objects; a DataFrame holds rows with a schema, so Spark can optimise the query for you.

What to try

        
Trigger interval: longer means bigger batches and higher latency, but less overhead per row.

        
Watermark delay: how long Spark waits for late data. The watermark is max event time seen − delay. Once it passes a window's end, that window is finalised, its state is freed, and later events for it are dropped.

        
Set the delay to 0 and watch the dropped count climb. Set it to 12 and windows stay open longer, which costs memory.

      

    

  







  
05 · Machine learning

  
MLlib: pipelines and distributed training

  
MLlib builds models from two kinds of parts. A Transformer turns one DataFrame into another by adding columns. An Estimator learns from a DataFrame and produces a Transformer (the fitted model). A Pipeline chains them.

Why this parallelises

        
Assign is a map: each executor labels the points in its own partitions with the nearest centroid. No executor needs another's data.

        
Update is a reduce: executors send per-cluster sums and counts, and the driver averages them into new centroids, then broadcasts them for the next round.

        
Only the small centroid list moves between rounds, never the dataset. Most MLlib algorithms follow this pattern. Click the canvas to add points.
